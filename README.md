# AR — Archaeology Reference（試作）

紙の図面にスマホをかざすと、図面の元になった遺構・遺物の3Dモデルが図面に重なり、資料情報と注記
（アノテーション）が出る静的サイト。サーバー処理なし。ライブラリはすべて `lib/` に同梱し、外部への通信はしない。

| 展示パネル | このサイトでの対応 |
|---|---|
| A-01 同時確認 | `ar.html`。モデルを図面と同じ位置・縮尺・方位で重ねる（`display.mode = plan`）。「透かす」で下の図面の線と見比べる。位置合わせは `tools/align.html` |
| A-02 共同参照 | 資料・注記ごとのリンク（パネルの「リンクを渡す」）、`viewer.html` での図面つき表示、`notes.html` の注記一覧（CSV・印刷）、データ版の表示 |
| A-03 利用環境 | ブラウザだけで動く。展示用の印刷シート（図面＋QR＋使い方）は `tools/sheet.html` |

## 構成

```
index.html          一覧
ar.html             AR表示（?t=図面のid でその図面のモデルを、?id=資料のid でその資料を先に読み込む）
viewer.html         通常の3D表示（?id=資料のid&note=遺構番号）。図面を持っていない人・カメラが使えないとき用
notes.html          注記一覧（?id=資料のid で絞り込み）。CSV保存・印刷
tools/              管理用：ファイルの確認、認識用データの作成、位置合わせ（align.html）、
                    展示用シート（sheet.html）、図形と表の照合（match.html）
data/               差し替えるファイルすべて（下の「決まったファイル名」）
lib/ js/ css/       同梱ライブラリと本体
```

### 決まったファイル名

ファイルの場所と名前はコードで決まっている。**`data/` の中のファイルを同じ名前のまま上書きすれば、そのまま動く**（コードは書き換えない）。

| ファイル | 中身 | 無いとき |
|---|---|---|
| `data/items.json` | 台帳（題名、図面画像の実寸、モデルの上の向き） | 動かない |
| `data/all.mind` | 認識用データ（図面画像から作る） | AR が動かない |
| `data/image.jpg` | 図面画像。**印刷するものと同じ画像** | 認識用データの作成・位置合わせ・ビューアの図面表示ができない |
| `data/model.glb` | 3Dモデル | 表示できない |
| `data/annotation.glb` | 注記の図形（オブジェクト名＝遺構番号） | 注記なしで表示する |
| `data/annotation.csv` | 注記の表（遺構一覧表） | 図形だけを、オブジェクト名で表示する |
| `data/meta.json` | 資料情報 | 資料情報を出さない |

図面や資料を2つ以上にするときは、`data/<id>/` に分けて同じ名前で置く（1つしかないものは `data/` にそのまま。
`all.mind` は図面が何枚でも `data/all.mind` の1つ）。`<id>` は台帳の `id`、省略すると並び順の番号（`data/1/`、`data/2/`…）。
置き場所は台帳の `"folder": "data/xxx/"` で変えられる。

差し替えたら、`tools/` の「0. ファイルの確認」を開く。ファイルの有無と、組み合わせの食い違い
（`all.mind` と図面画像の縦横比、モデルの上の向き、注記の図形とモデルの座標、表の見出しと図形との対応）を一覧で出す。

本体のうち追跡に関わるもの：`js/tracking.js`（MindAR の追跡処理の差し替え）、
`js/oblique.js`（斜めから見た図面を探すための計算）、
`js/stabilizer.js`（表示の揺れ止めと、見失ったときの固定表示）、
`js/trackpoints.js`（追跡用の手がかりの選び直しと、近づいたとき用の細かい見本）、
`js/levels-worker.js`（細かい見本が all.mind に無いときに、AR の画面で図面画像から作る）。

## 公開（GitHub Pages）

1. このフォルダの中身をリポジトリの最上位に置いて push する。
2. Settings → Pages → Branch を `main` / `(root)` にする。
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く。

カメラは HTTPS でしか動かない。PCでの確認は、このフォルダで `python -m http.server` を実行し
`http://localhost:8000/` を開く。スマホ実機での確認は Pages に上げてから行う。

図面画像（`image.jpg`）は公開サイトから誰でも取り出せ、ビューアでもモデルの下に敷いて表示する。
権利の確認が取れていない図版は、台帳の図面に `"viewerImage": false` を書いてビューアに出さないようにし、
`image.jpg` はリポジトリに入れない（認識用データの作成と位置合わせは手元で `python -m http.server` を使って行い、
`all.mind` と台帳だけを公開する。台帳には図面画像の大きさ `widthPx`・`heightPx` を残しておく）。

## 図面とモデルを重ねる（実寸と座標）

図面画像の実寸（m）を台帳に書き、3Dモデルは図面画像と同じ座標で作る。これだけで、AR でも3D表示でも
モデルが図面の上の正しい位置・縮尺・向きに重なる（位置合わせの数値は要らない）。

```json
"targets": [ { "title": "第7図 23-2トレンチ平・断面図", "realWidthM": 33.65, "realHeightM": 23.7983 } ]
```

| 項目 | 内容 |
|---|---|
| `realWidthM` / `realHeightM` | `image.jpg` 全体の実寸（横・縦、m）。縮尺 1/80 の図面を 240dpi で画像にしたなら、画素数 ÷ 240 × 25.4 ÷ 1000 × 80。片方だけでもよい。両方書いて画像の縦横比と 0.5% 以上違うと、一覧と `tools/` に注意が出る |

モデルの座標は、**図面画像の左下を原点、右を X、上を Y、単位 m**（Blender の座標）。Blender で図面画像を
実寸の板にして原点から敷き（左下が原点）、その上でモデルの位置・向きを合わせ、いつもどおり書き出す（「+Y上」のまま）。
`model.rotationDeg` は `[0, 0, 0]`。注記の `annotation.glb` も同じ座標で書き出す。

- 縮尺は画素ではなく実寸で決まるので、図面画像を別の解像度で書き出し直しても、実寸を書き換えなくてよい。
- 実寸がわからないときは、位置合わせページ（`tools/align.html`）で縮尺バーを測ると実寸が入る。
- 図面と同じ座標で作っていないモデルは、位置合わせページで動かして合わせる（`display.at`・`headingDeg` が保存される）。

## ファイルを差し替える

| 差し替えるもの | すること |
|---|---|
| 注記（`annotation.glb`・`annotation.csv`） | 上書きするだけ。`tools/match.html` で図形と表の対応を確かめる |
| 3Dモデル（`model.glb`） | 上書きするだけ。図面画像と同じ座標で作ってあれば、そのまま重なる |
| 図面画像（`image.jpg`） | 上書きして、`tools/` で `all.mind` を作り直して置き換える（MindAR 公式の作成ページで作ったものでもよい） |
| 認識用データ（`all.mind`） | 上書きするだけ。図面画像と組で差し替える |

- 図面画像の画素数は画像から読む。図面画像を差し替えたら、台帳の実寸（`realWidthM`・`realHeightM`）を新しい画像の実寸にする。
- 図面の範囲（切り抜き方）が変わると、モデルの座標の原点（画像の左下）も変わる。Blender で敷く図面画像も同じものにする。
- `all.mind` と図面画像の縦横比が違うと、AR 画面の上に赤い注意が出る（片方だけ差し替えたとき）。

## 図面と資料を追加する

1. モデルを軽くする（目安：テクスチャ 2048px 以下、5MB 前後。1枚の図面に3つ以上載せるなら 1024px）。
   `npx @gltf-transform/cli resize in.glb a.glb --width 2048 --height 2048`
   `npx @gltf-transform/cli draco a.glb model.glb`
   単位はメートルで書き出す。
2. `data/items.json` の `targets` に図面を、`items` に資料を足す（資料の `target` に図面の `id`）。
3. 2つ目からはフォルダを分ける：資料のファイル（`model.glb`・`annotation.glb`・`annotation.csv`・`meta.json`）を
   `data/<資料のid>/` に、図面画像を `data/<図面のid>/image.jpg` に置く。いま `data/` にある1つ目のファイルは、
   1つ目にも `"folder": "data/"` を書けば動かさずに済む。
4. `tools/` で「作成する」→ 保存した `all.mind` で `data/all.mind` を置き換える。
5. 台帳の図面に実寸（`realWidthM`・`realHeightM`）を書く。モデルを図面と同じ座標で作っていなければ、
   `tools/` の「位置合わせ」でモデルを図面に合わせ、保存した `items.json` で台帳を置き換える。
6. `tools/sheet.html` に公開URLを入れて、展示用シートを印刷する。

印刷後に変えられないもの：公開URL（QRに入る）と図面画像（変えると配布済みの紙が反応しなくなる）。

## 台帳（data/items.json）

### site

| 項目 | 内容 |
|---|---|
| `title` / `lead` | 一覧の見出しと説明 |
| `edition` | データの版（例 `2026-10-21`）。一覧・パネル・注記一覧・シートに出る。共同参照で「同じ版を見ているか」を確かめるため、資料を直したら更新する |
| `cite` | 引用のしかた（DOI など）。省略可 |
| `notice` | 一覧の上に出す注意書き。省略可 |

### targets（図面）

並び順が `all.mind` の中の順番になる。途中に挟んだり並べ替えたりしたら `all.mind` を作り直す。

| 項目 | 内容 |
|---|---|
| `id` / `title` | 図面の id（URL `ar.html?t=` と、2つ以上のときのフォルダ名。省略すると並び順の番号）と表示名 |
| `realWidthM` / `realHeightM` | 図面画像全体の実寸（m）。上の「図面とモデルを重ねる」 |
| `widthPx` / `heightPx` | `display.at` を決めたときの図面画像の画素数（位置合わせページが書く）。図面画像を書き出し直したときの換算に使う。モデルの座標で重ねるときは不要 |
| `credit` | 図面の出典。シートに出る（省略可） |
| `viewerImage` | `false` でビューアに図面を敷かない（省略時は `image.jpg` を敷く） |
| `source` | 図面画像を決まった場所以外に置くときだけ書く |

### items（資料）

| 項目 | 内容 |
|---|---|
| `id` / `title` / `subtitle` | 資料の id（URL `?id=` と、2つ以上のときのフォルダ名。省略すると並び順の番号）と表示名 |
| `target` | 載っている図面の id（図面が1枚なら省略可） |
| `model.rotationDeg` | 向きの補正 `[x, y, z]`（度）。上が +Y になるようにする。Blender で「+Y上」を外して書き出したモデル（Z が上）は `[-90, 0, 0]`。位置合わせページの「モデルの上の向き」で選べる |
| `model.metersPerUnit` | モデルの1単位が何mか（省略時 1） |
| `display.mode` | `plan`＝平面図に重ねる（遺構）／`stand`＝紙の上に立たせる／`lay`＝正面図に重ねて寝かせる（遺物） |
| `display.at` | 置き場所。図面画像の画素 `[横, 縦]`。モデルの水平方向の中心がここに来る。書かなければ、モデルの座標のまま重ねる（図面の実寸が書いてあるとき） |
| `display.headingDeg` | 方位。モデルの北を、図面の上から時計回りに何度回すか（`display.at` を書いたときだけ） |
| `display.ground` | 紙の面に合わせる高さ。`"top"`＝上端（plan の既定。遺構を検出した面が紙に来る）、`"bottom"`＝下端、数値＝下端から何m |
| `display.size` | 大きさ。plan では省略すると図面の実寸で決まる。縮尺の違う図が同じ画像にある場合は `{"type":"drawing","pxPerMeter":…}` でその資料だけ変える。`{"type":"fit","value":0.35}`＝図面幅の35% |
| `annotations` | 省略可。表の列の読み方を変えるとき（下の「表の読み方」）や、`false` で注記を使わないときに書く |
| `meta` | `false` で資料情報を読まない（省略可） |

ファイルの場所（`model.src`、`annotations.glb`・`annotations.table`、`meta`）を書けば、決まった場所以外のファイルも使える。
旧形式（資料ごとに `target` の中身と `targetIndex` を書く形）や、縮尺を画素で書いた台帳（`pxPerMeter`）も読める。

## 追跡の調整

モデルが揺れる・消えるときは、まず `ar.html?debug=1` で開いて画面左上の数字を見る。

| 表示 | 見方 |
|---|---|
| 認識 n回/秒 | 追跡処理の速さ。10を下回ると動きに追いつけず見失いやすい |
| 手がかり n点 | そのコマで図面と合った目印の数。6点未満のコマは姿勢の更新に使わない |
| 見本 n | いま使っている見本の細かさ（短辺の画素数）。128 が標準、近づくと 256・384・576・864 に移る。カッコ内は持っている見本 |
| 直近の試し | そのコマで試した見本と、合った目印の数（`384予:30/28` ＝ 384 の見本で、動きを見込んだ位置から探して30点、取り違えを除いて28点。`合` は見つけ直した直後の合わせ込み） |
| 発見 | 図面を探して見つけた回数 |
| 探索 正面 a/b 傾50 a/b … | 探し方ごとの成功回数／試した回数。正面＝MindAR既定、傾50・傾65＝その傾きを仮定、前回＝最後に追跡できた向きを仮定。どれも b ばかり増えるなら、探す段階でつまずいている |
| 却下 | 見つけた直後に追跡へ移れず、探し直した回数 |
| 探し直し / 見失い | 追跡をあきらめて図面を探し直した回数／表示を固定に切り替えた回数 |
| 作り直し | 追跡の処理が止まったのを検知して、自動で作り直した回数 |
| エラー | 追跡の処理で出た例外の数と、最後の内容 |
| 映像 | カメラ映像の画素数 |

設定は台帳の最上位に `"tracking": { ... }` を足すと変えられる。同じ名前をURLに付けて
試すこともできる（例 `ar.html?debug=1&stillCutoff=0.3`）。

| 項目 | 既定 | 内容 |
|---|---|---|
| `stillCutoff` | 0.5 | 手を止めているときの揺れ止めの強さ。小さいほど揺れないが、動き出しが遅れる |
| `posFollow` / `rotFollow` | 15 / 7 | 動かしたときに追従を速める度合い（位置／向き）。大きいほど遅れないが揺れが残る |
| `hold` | 1 | 1＝見失っても最後の姿勢で表示を残す。0＝消す |
| `lostAfterMs` | 800 | 姿勢が得られない状態が何ミリ秒続いたら「見失った」とするか |
| `minPoints` | 6 | 姿勢の更新に使う手がかりの最少数 |
| `retryFrames` | 8 | 追跡に失敗しても、図面の探し直しに戻らず粘るコマ数 |
| `rejectOutliers` | 1 | 1＝周りと食い違う手がかりを姿勢の計算から外す |
| `obliqueSearch` | 1 | 1＝斜めから見た図面も探す |
| `searchTilts` | [50, 65] | 斜めの探索で仮定する傾き（度）。図面の奥側が画面の上に来る向き。机の上の図面を想定 |
| `searchSideTilts` | [] | 同上、奥側が画面の左右に来る向き。壁に貼った図面を横から見る場合に `[50]` などを入れる |
| `warmupTolerance` | 2 | 表示を始めるまでに必要な連続成功コマ数 |
| `cameraLongSide` | 0 | カメラ映像の長辺の希望画素数（0＝ブラウザ任せ）。実機では未確認 |
| `multiLevel` | 1 | 1＝近づいたら細かい見本に切り替える（下の「近づいて図面の一部を見るとき」） |
| `levelRatio` | 3 | 見本1画素に映像の何画素が対応するのがよいか。大きくすると速い動きに強くなるが、細い線を拾いにくくなる |
| `predict` | 1 | 1＝速く動かしているときは、直前の動きから次の位置を見込んで探す |
| `resumeMs` | 5000 | 見失ってからこの時間（ミリ秒）は、図面を探すのと交互に「最後に追えていた位置」でも確かめる |
| `stallMs` | 3000 | 1コマの処理がこの時間（ミリ秒）を超えたら、止まったとみなして追跡を作り直す |

### 見失ったとき

画面に「図面を見失いました」と出ている間、モデルは最後の位置のまま画面に残る。
図面を画面いっぱいに映し直すと自動で追跡に戻る。戻らないときは「探し直す」を押すと、
カメラと追跡を作り直す（ページの再読み込みは不要）。

図面は近いほど見つけやすい。擬似映像での1回あたりの成功率は、図面が画面からはみ出す近さで約9割、
画面幅の8割で約6割、画面幅の半分で約3割だった。

### 近づいて図面の一部を見るとき

追い続けるときは、図面を縮めた「見本」と映像を見比べている。MindAR 標準の見本は短辺128画素の1種類だけで、
図面全体が画面に入っている前提の粗さなので、近づいて図面の一部を大きく写すと、見本の1画素に映像の何画素もが
対応して細い線が拾えなくなり、すぐ見失っていた。

そこで、細かさの違う見本（短辺 256・384・576・864 画素）を足し、図面が画面にどれくらいの大きさで写っているかで
切り替える。図面全体を写しているときは標準の見本、近づくにつれて細かい見本に移る。あわせて、

- 速く動かしているときは、直前の動きから次の位置を見込んで探す
- 図面を見つけ直した直後は、粗い見本から細かい見本へ順に合わせ込む（近くで見つけ直した位置は数十画素ずれることがある）
- 見失ってから5秒間は、図面を探すのと交互に「最後に追えていた位置」でも確かめる

細かい見本は、`tools/` で `all.mind` を作るときに入る（「近づいたとき用」の欄）。入っていない `all.mind`
（MindAR の公式ページで作ったものなど）でも、AR の画面で図面画像から作り、数秒後から使う（そのあいだは標準の見本で追う）。
`?debug=1` の「見本」が、いま使っている見本の短辺の画素数。

近くで図面を見つけ直すのは、図面全体が写っているときより苦手（写っている範囲の目印が少ないため）。
見失ったら、少し離して図面の広い範囲を写すと早く戻る。

### 斜めから見たとき

MindAR 既定の探し方は正面に近い見え方が前提で、傾き（真上から見たときを0°とする）が45°で成功率2割、
55°以上ではほぼ0になる。そこで、映像を「図面と正対したらこう見える」形に直してから探す方法を
1コマおきに挟んでいる。傾きは事前にわからないので、50°と65°を仮定して順に試し、
一度追跡できたあとは、そのときの向きも候補に加える。

擬似映像では、傾き45〜65°で、仮定が合った回はほぼ毎回見つかった。72°では見つかるが、
その後の追跡が続かない（手がかりが4点前後しか合わない）。実用になるのは65°くらいまで。

## 資料情報（meta.json）

`data/meta.json`。無くてもよい。

```json
{ "title": "表示名", "fields": [ { "label": "遺跡名", "value": "" } ], "notice": "" }
```

`value` が空の項目は画面に出ない。

## 注記（annotation.glb と annotation.csv）

現場で作った図面（ベクトルデータ）と遺構一覧表をそのまま使う。注記のために新しく文字を書いたり、
表を作り直したりしない。

| ファイル | 中身 | 使う情報 |
|---|---|---|
| `annotation.glb` | 図面のベクトルデータを Blender に読み込み、3Dモデルに重ねて書き出した図形 | 形・位置と、オブジェクト名（＝遺構番号）だけ。図面データの属性・カスタムプロパティ・色は使わない |
| `annotation.csv` | 現場で作った遺構一覧表 | 文字はすべてここから |

図形と表は「オブジェクト名 ＝ 表の遺構番号」でつなぐ。全角・半角、大文字・小文字、空白の違いは同じ番号とみなす
（`ＳＫ０２` と `SK02` は同じ）。オブジェクト名の末尾の `.001` などは外すので、1つの遺構を複数の図形で
描いたもの（上端と下端など）は1つの注記になる。

### サンプル

基壇の図面で作った注記のサンプル（`annotation.glb`・`annotation.csv`）は v14 に入っている（いまのデータは 23-2トレンチで、注記はまだない）。

### 作り方

1. 3Dモデル（`model.glb` を書き出した Blender のファイル）に、図面のベクトルデータを読み込んで重ねる。
   **モデルは動かさない**（動かすのは図面のベクトルデータ）。モデルと同じ座標で図形を書き出すため。
2. 図形を表面に沿わせる（シュリンクラップ モディファイアーの「投影」で -Z 方向など）。点はエンプティでよい。
3. 注記にする図形のオブジェクト名を遺構番号にする（`SI01`、`P3`、`SK02` など）。
4. 図形だけを選んで `data/annotation.glb` として書き出す。設定は次のとおり。
   - 「含む → 選択したオブジェクト」
   - 「データ → メッシュ → **ルーズエッジ（Loose Edges）**」と「**ルーズポイント（Loose Points）**」。
     入れないと、線と点は書き出されずに消える（Blender の既定は入っていない）
   - シュリンクラップなどのモディファイアーを使ったら「データ → メッシュ → **モディファイアーを適用**」も入れる
   - 「**+Y上**」は `model.glb` と同じにする（いまのモデルは Z が上＝「+Y上」を外して書き出したのと同じ形なので、外す）。
     圧縮（Draco・gltf-transform）はかけない
5. 遺構一覧表を CSV で保存して `data/annotation.csv` に置く（Excel の「CSV」でも「CSV UTF-8」でもよい）。
6. `tools/` の「ファイルの確認」と `tools/match.html` で、図形と表の対応と、モデルとの座標のずれを確かめる。

`model.glb` を読み込み直して作る場合、Z が上のモデルは横倒しで読み込まれる。そのときは 3D カーソルを原点に置き、
ピボットを「3D カーソル」にして、読み込んだもの全体を X 軸で -90° 回してから作業する（原点の周りに回さないと座標がずれる）。

### 表の読み方

台帳に何も書かなければ、次のように読む。

| 役目 | 既定 | 台帳で変えるとき |
|---|---|---|
| 遺構番号 | 見出し行の左端の列 | `"key": "遺構番号"` |
| まとまり（表示の切り替え） | 「種別」「種類」「分類」の列。無ければ点・線・面ごと | `"layer": "列名"` |
| 説明 | 「備考」「説明」の列 | `"note": "列名"` |
| 名前 | 「名称」の列。無ければ遺構番号 | `"label": "列名"` |

```json
"annotations": { "key": "遺構番号", "layer": "種別", "note": "備考" }
```

- 見出し行は、文字の入ったセルが2つ以上ある最初の行（`key` を書いたときは、その列名を含む行）。
  表の上に表題や作成日の行（1セルだけの行）があってもよい。
- 上の役目以外の列は、列名のまま項目としてパネルと注記一覧に出る（空の欄は出さない）。
- 文字コードは UTF-8 と Shift_JIS のどちらでもよい（自動で見分ける）。
- 1つの表を複数の資料で使い回せる。表にあってその資料の図形に無い遺構は、その資料に載っていないだけなので問題にしない。
- 図形にあって表に無いもの（調査区の境界、断面の位置など）は表示しない。遺構番号の打ち間違いもここに入るので、
  照合ツールで確かめる（数字が同じ番号や、1〜2文字違いの番号を候補として出す）。
- 表で同じ遺構番号が2回出てきたら、後の行は使わない（注記一覧と照合ツールに出る）。
- 注記へのリンク（`?note=SK02`）は遺構番号になる。

### 種類（点・線・面）

形だけで決まる。エンプティ・1点だけのもの＝点、開いた線＝線、閉じた線・面のあるメッシュ＝面。
同じ遺構番号に閉じた線と開いた線があれば面にする（開いた線も、開いたまま描く）。
面のあるメッシュは半透明に塗る。

### JSON で書いた注記（従来の形）

台帳に `"annotations": "data/x/annotations.json"` と書けば、JSON で書いた注記も使える。
レイヤー単位で `uid`・`Annotation_Type`（Point / Line / Area）・`metadata` を持ち、
座標は GLB を読み込んだときの座標（`rotationDeg` をかける前）。

```json
{
  "coordinate": "glb",
  "layers": [
    { "uid": "…", "name": "Point_001", "Annotation_Type": "Point", "color": "#ff3b30",
      "metadata": { "内容": "…" },
      "items": [ { "label": "1", "note": "…", "position": [x, y, z] } ] },
    { "uid": "…", "name": "Line_001", "Annotation_Type": "Line",
      "items": [ { "points": [[x, y, z], [x, y, z]] } ] }
  ]
}
```

## 制限

- iPhone は iOS 16.4 以降の Safari。LINE や X のアプリ内ブラウザではカメラが動かないことがある。
- 白地に細い線だけの図面は認識できない。`tools/` の「追跡用」の数で事前に確かめる。
- 揺れ止めのため、端末を速く動かすとモデルが図面より少し遅れて動く。
- 図面が画面から外れるとモデルは画面上で固定される（図面を画面いっぱいに映し直すと追跡に復帰する）。
- 斜めから見られるのは傾き65°くらいまで。それより寝かせた角度では追跡が続かない。
- 近づいて一部を見るときは、図面全体を写した状態から近づくと途切れにくい。近くで見失うと、見つけ直すのに時間がかかることがある。
  擬似映像では、A3 の図面に 17cm まで近づいて動かしても途切れず（従来は近づいた時点で見失っていた）、10cm では7割ほどのコマで追えた。
  スマホのカメラは近すぎるとピントが合わない（機種により 10〜15cm より近いと合わない）。
- 遺構配置図のように縮尺の小さい図面では、1つの遺構が紙の上で1〜2cmにしかならない。重なりは正しくても
  小さくて見にくいので、個々の遺構の平面図（1/40〜1/60 など）を対象にするか、大きく印刷する。
- 位置の正確さは追跡の精度で決まる。擬似映像では、図面上の置き場所と映像上の位置のずれは中央値で約1画素
  （映像幅480画素）、図面画像に直して約4画素だった。
- 同時に追う図面は1枚。読み込んだモデルは2件まで保持し、古いものから捨てる。
