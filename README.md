# AR — Archaeology Reference（試作）

紙の図面にスマホをかざすと、図面の元になった遺構・遺物の3Dモデルが図面に重なり、資料情報と注記
（アノテーション）が出る静的サイト。サーバー処理なし。ライブラリはすべて `lib/` に同梱し、外部への通信はしない。

| 展示パネル | このサイトでの対応 |
|---|---|
| A-01 同時確認 | `ar.html`。モデルを図面と同じ位置・縮尺・方位で重ねる（`display.mode = plan`）。「透かす」で下の図面の線と見比べる。位置合わせは `tools/align.html` |
| A-02 共同参照 | 資料・注記ごとのリンク（パネルの「リンクを渡す」）、`viewer.html` での図面つき表示、`notes.html` の注記一覧（CSV・印刷）、データ版の表示 |
| A-03 利用環境 | ブラウザだけで動く。展示用の印刷シート（図面＋QR＋使い方）は `tools/sheet.html` |

## 構成

```
index.html          一覧
ar.html             AR表示（?t=図面ID でその図面のモデルを、?id=資料ID でその資料を先に読み込む）
viewer.html         通常の3D表示（?id=資料ID&note=注記）。図面を持っていない人・カメラが使えないとき用
notes.html          注記一覧（?id=資料ID で絞り込み）。CSV保存・印刷
tools/              管理用：認識用データの作成、位置合わせ（align.html）、展示用シート（sheet.html）
data/items.json     台帳（図面 targets と資料 items）
data/<資料ID>/      model.glb / meta.json / annotations.json
targets/all.mind    認識用データ（全図面をまとめた1ファイル）
targets/src/        図面画像（認識用データの元、位置合わせ、印刷、ビューアの図面表示に使う）
lib/ js/ css/       同梱ライブラリと本体
```

本体のうち追跡に関わるもの：`js/tracking.js`（MindAR の追跡処理の差し替え）、
`js/oblique.js`（斜めから見た図面を探すための計算）、
`js/stabilizer.js`（表示の揺れ止めと、見失ったときの固定表示）、
`tools/trackpoints.js`（追跡用の手がかりの選び直し）。

## 公開（GitHub Pages）

1. このフォルダの中身をリポジトリの最上位に置いて push する。
2. Settings → Pages → Branch を `main` / `(root)` にする。
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く。

カメラは HTTPS でしか動かない。PCでの確認は、このフォルダで `python -m http.server` を実行し
`http://localhost:8000/` を開く。スマホ実機での確認は Pages に上げてから行う。

`targets/src/` の図面画像は公開サイトから誰でも取り出せる。`viewerImage` を書くとビューアにも表示される。
権利の確認が取れていない図版は `viewerImage` を書かず、リポジトリにも入れない（認識用データの作成と位置合わせは
手元で `python -m http.server` を使って行い、`all.mind` と台帳だけを公開する）。

## 図面と資料を追加する

1. モデルを軽くする（目安：テクスチャ 2048px 以下、5MB 前後。1枚の図面に3つ以上載せるなら 1024px）。
   `npx @gltf-transform/cli resize in.glb a.glb --width 2048 --height 2048`
   `npx @gltf-transform/cli draco a.glb model.glb`
   遺構は北を -Z（Blender では +Y）、単位をメートルで書き出す。
2. `data/<資料ID>/` に `model.glb`、`meta.json`、`annotations.json` を置く。
3. 図面画像を `targets/src/<図面ID>.jpg` に置く。**印刷するものと同じ画像**を使う。
4. `data/items.json` の `targets` に図面を、`items` に資料を足す（資料の `target` に図面ID）。
5. `tools/` で「作成する」→ 保存した `all.mind` を `targets/all.mind` に置き換える（図面を足したときだけ）。
6. `tools/` の「位置合わせ」で、モデルを図面に合わせる → 保存した `items.json` で台帳を置き換える。
7. `tools/sheet.html` に公開URLを入れて、展示用シートを印刷する。

印刷後に変えられないもの：公開URL（QRに入る）と図面画像（変えると配布済みの紙が反応しなくなる）。

## 台帳（data/items.json）

### site

| 項目 | 内容 |
|---|---|
| `title` / `lead` | 一覧の見出しと説明 |
| `edition` | データの版（例 `2026-10-21`）。一覧・パネル・注記一覧・シートに出る。共同参照で「同じ版を見ているか」を確かめるため、資料を直したら更新する |
| `cite` | 引用のしかた（DOI など）。省略可 |
| `notice` | 一覧の上に出す注意書き。省略可 |

### targets（図面）

並び順が `all.mind` の中の順番になる。途中に挟んだり並べ替えたりしたら `all.mind` を作り直す。

| 項目 | 内容 |
|---|---|
| `id` / `title` | 図面ID（URL `ar.html?t=` に使う）と表示名 |
| `source` | 図面画像の場所 |
| `widthPx` / `heightPx` | 図面画像の画素数 |
| `pxPerMeter` | 図面画像で 1m が何画素か。位置合わせページで縮尺バーを測ると入る |
| `credit` | 図面の出典。シートに出る |
| `viewerImage` | ビューアで3Dモデルの下に敷く図面画像。書かなければ敷かない |

### items（資料）

| 項目 | 内容 |
|---|---|
| `id` / `title` / `subtitle` | 資料ID（URL とフォルダ名）と表示名 |
| `target` | 載っている図面の ID |
| `model.src` | モデルの場所 |
| `model.rotationDeg` | 向きの補正 `[x, y, z]`（度）。上が +Y になるようにする |
| `model.metersPerUnit` | モデルの1単位が何mか（省略時 1） |
| `display.mode` | `plan`＝平面図に重ねる（遺構）／`stand`＝紙の上に立たせる／`lay`＝正面図に重ねて寝かせる（遺物） |
| `display.at` | 置き場所。図面画像の画素 `[横, 縦]`。モデルの水平方向の中心がここに来る |
| `display.headingDeg` | 方位。モデルの北を、図面の上から時計回りに何度回すか |
| `display.ground` | 紙の面に合わせる高さ。`"top"`＝上端（plan の既定。遺構を検出した面が紙に来る）、`"bottom"`＝下端、数値＝下端から何m |
| `display.size` | 大きさ。plan では省略すると図面の縮尺（`pxPerMeter`）で決まる。`{"type":"fit","value":0.35}`＝図面幅の35% |
| `meta` | 資料情報（JSON）の場所（省略可） |
| `annotations` | 注記の場所（省略可）。JSON なら `"data/x/annotations.json"`、図面のベクトルデータと遺構一覧表なら下の「図面のベクトルデータと遺構一覧表で付ける」の形 |

旧形式（資料ごとに `target` の中身と `targetIndex` を書く形）も読める。

## 追跡の調整

モデルが揺れる・消えるときは、まず `ar.html?debug=1` で開いて画面左上の数字を見る。

| 表示 | 見方 |
|---|---|
| 認識 n回/秒 | 追跡処理の速さ。10を下回ると動きに追いつけず見失いやすい |
| 手がかり n点 | そのコマで図面と合った目印の数。6点未満のコマは姿勢の更新に使わない |
| 発見 | 図面を探して見つけた回数 |
| 探索 正面 a/b 傾50 a/b … | 探し方ごとの成功回数／試した回数。正面＝MindAR既定、傾50・傾65＝その傾きを仮定、前回＝最後に追跡できた向きを仮定。どれも b ばかり増えるなら、探す段階でつまずいている |
| 却下 | 見つけた直後に追跡へ移れず、探し直した回数 |
| 探し直し / 見失い | 追跡をあきらめて図面を探し直した回数／表示を固定に切り替えた回数 |
| 作り直し | 追跡の処理が止まったのを検知して、自動で作り直した回数 |
| エラー | 追跡の処理で出た例外の数と、最後の内容 |
| 映像 | カメラ映像の画素数 |

設定は台帳の最上位に `"tracking": { ... }` を足すと変えられる。同じ名前をURLに付けて
試すこともできる（例 `ar.html?debug=1&stillCutoff=0.3`）。

| 項目 | 既定 | 内容 |
|---|---|---|
| `stillCutoff` | 0.5 | 手を止めているときの揺れ止めの強さ。小さいほど揺れないが、動き出しが遅れる |
| `posFollow` / `rotFollow` | 15 / 7 | 動かしたときに追従を速める度合い（位置／向き）。大きいほど遅れないが揺れが残る |
| `hold` | 1 | 1＝見失っても最後の姿勢で表示を残す。0＝消す |
| `lostAfterMs` | 800 | 姿勢が得られない状態が何ミリ秒続いたら「見失った」とするか |
| `minPoints` | 6 | 姿勢の更新に使う手がかりの最少数 |
| `retryFrames` | 8 | 追跡に失敗しても、図面の探し直しに戻らず粘るコマ数 |
| `rejectOutliers` | 1 | 1＝周りと食い違う手がかりを姿勢の計算から外す |
| `obliqueSearch` | 1 | 1＝斜めから見た図面も探す |
| `searchTilts` | [50, 65] | 斜めの探索で仮定する傾き（度）。図面の奥側が画面の上に来る向き。机の上の図面を想定 |
| `searchSideTilts` | [] | 同上、奥側が画面の左右に来る向き。壁に貼った図面を横から見る場合に `[50]` などを入れる |
| `warmupTolerance` | 2 | 表示を始めるまでに必要な連続成功コマ数 |
| `cameraLongSide` | 0 | カメラ映像の長辺の希望画素数（0＝ブラウザ任せ）。実機では未確認 |

### 見失ったとき

画面に「図面を見失いました」と出ている間、モデルは最後の位置のまま画面に残る。
図面を画面いっぱいに映し直すと自動で追跡に戻る。戻らないときは「探し直す」を押すと、
カメラと追跡を作り直す（ページの再読み込みは不要）。

図面は近いほど見つけやすい。擬似映像での1回あたりの成功率は、図面が画面からはみ出す近さで約9割、
画面幅の8割で約6割、画面幅の半分で約3割だった。

### 斜めから見たとき

MindAR 既定の探し方は正面に近い見え方が前提で、傾き（真上から見たときを0°とする）が45°で成功率2割、
55°以上ではほぼ0になる。そこで、映像を「図面と正対したらこう見える」形に直してから探す方法を
1コマおきに挟んでいる。傾きは事前にわからないので、50°と65°を仮定して順に試し、
一度追跡できたあとは、そのときの向きも候補に加える。

擬似映像では、傾き45〜65°で、仮定が合った回はほぼ毎回見つかった。72°では見つかるが、
その後の追跡が続かない（手がかりが4点前後しか合わない）。実用になるのは65°くらいまで。

## 資料情報（meta.json）

```json
{ "title": "表示名", "fields": [ { "label": "遺跡名", "value": "" } ], "notice": "" }
```

`value` が空の項目は画面に出ない。

## アノテーション（annotations.json）

レイヤー単位で `uid`・`Annotation_Type`（Point / Line / Area）・`metadata` を持つ。
座標は **GLBを読み込んだときの座標**（`rotationDeg` をかける前）。

```json
{
  "coordinate": "glb",
  "layers": [
    { "uid": "…", "name": "Point_001", "Annotation_Type": "Point", "color": "#ff3b30",
      "metadata": { "内容": "…" },
      "items": [ { "label": "1", "note": "…", "position": [x, y, z] } ] },
    { "uid": "…", "name": "Line_001", "Annotation_Type": "Line",
      "items": [ { "points": [[x, y, z], [x, y, z]] } ] },
    { "uid": "…", "name": "Area_001", "Annotation_Type": "Area",
      "items": [ { "points": [[x, y, z], [x, y, z], [x, y, z]] } ] }
  ]
}
```

Area は境界線だけを描き、終点から始点へ自動で閉じる（面の塗りは未対応）。

### 図面のベクトルデータと遺構一覧表で付ける

現場で作った図面（ベクトルデータ）と遺構一覧表をそのまま使う。注記のために新しく文字を書いたり、
表を作り直したりしない。

| 使うもの | 中身 | 使う情報 |
|---|---|---|
| 図形 `notes.glb` | 図面のベクトルデータを Blender に読み込み、3Dモデルに重ねて書き出したもの | 形・位置と、オブジェクト名（＝遺構番号）だけ。図面データの属性・カスタムプロパティ・色は使わない |
| 表（遺構一覧表の CSV） | 現場で作った一覧表 | 文字はすべてここから |

図形と表は「オブジェクト名 ＝ 表の遺構番号」でつなぐ。全角・半角、大文字・小文字、空白の違いは同じ番号とみなす
（`ＳＫ０２` と `SK02` は同じ）。オブジェクト名の末尾の `.001` などは外すので、1つの遺構を複数の図形で
描いたもの（上端と下端など）は1つの注記になる。

#### 手順

1. 図面のベクトルデータを Blender に読み込み、3Dモデルに重ねる（位置・高さを合わせる）。
2. 注記にする図形のオブジェクト名を遺構番号にする（`SI01`、`P3`、`SK02` など）。
3. 本体を書き出す（いつもどおり。選択したオブジェクトのみ、+Y上）。
4. 図形だけを選んで `data/<資料ID>/annotations/notes.glb` として書き出す。設定は次のとおり。
   - 「含む → 選択したオブジェクト」（または「アクティブなコレクション」）
   - 「データ → メッシュ → **ルーズエッジ（Loose Edges）**」と「**ルーズポイント（Loose Points）**」。
     入れないと、線と点は書き出されずに消える（Blender の既定は入っていない）
   - 「+Y上」は本体と同じ。圧縮（Draco・gltf-transform）はかけない
5. 遺構一覧表を CSV で保存して `data/tables/` に置く（Excel の「CSV」でも「CSV UTF-8」でもよい）。
6. 台帳に書く。

```json
"annotations": {
  "glb": "data/kidan/annotations/notes.glb",
  "table": "data/tables/遺構一覧.csv",
  "key": "遺構番号",
  "layer": "種別",
  "note": "備考"
}
```

| 項目 | 内容 |
|---|---|
| `key` | 遺構番号の列の見出し。必須（省略すると表の左端の列） |
| `layer` | 表示の切り替えのまとまりに使う列（例「種別」）。省略すると点・線・面ごと |
| `note` | パネルで説明として出す列（例「備考」）。省略可 |
| `label` | パネルで見出しとして出す列。省略すると遺構番号 |

7. `tools/match.html` で、図形と表の対応を確かめる。

#### 表の読み方

- `key` の列名を含む行を見出し行とみなす。表の上に表題や作成日の行があってもよい。
- `key`・`layer`・`note`・`label` 以外の列は、列名のまま項目としてパネルと注記一覧に出る（空の欄は出さない）。
- 1つの表を複数の資料で使い回せる。表にあってその資料の図形に無い遺構は、その資料に載っていないだけなので問題にしない。
- 図形にあって表に無いもの（調査区の境界、断面の位置など）は表示しない。遺構番号の打ち間違いもここに入るので、
  照合ツールで確かめる（数字が同じ番号や、1〜2文字違いの番号を候補として出す）。
- 表で同じ遺構番号が2回出てきたら、後の行は使わない（注記一覧と照合ツールに出る）。
- 注記へのリンク（`?note=SK02`）は遺構番号になる。

#### 種類（点・線・面）

形だけで決まる。エンプティ・1点だけのもの＝点、開いた線＝線、閉じた線・面のあるメッシュ＝面。
同じ遺構番号に閉じた線と開いた線があれば面にする（開いた線も、開いたまま描く）。
面のあるメッシュは半透明に塗る。

## 制限

- iPhone は iOS 16.4 以降の Safari。LINE や X のアプリ内ブラウザではカメラが動かないことがある。
- 白地に細い線だけの図面は認識できない。`tools/` の「追跡用」の数で事前に確かめる。
- 揺れ止めのため、端末を速く動かすとモデルが図面より少し遅れて動く。
- 図面が画面から外れるとモデルは画面上で固定される（図面を画面いっぱいに映し直すと追跡に復帰する）。
- 斜めから見られるのは傾き65°くらいまで。それより寝かせた角度では追跡が続かない。
- 遺構配置図のように縮尺の小さい図面では、1つの遺構が紙の上で1〜2cmにしかならない。重なりは正しくても
  小さくて見にくいので、個々の遺構の平面図（1/40〜1/60 など）を対象にするか、大きく印刷する。
- 位置の正確さは追跡の精度で決まる。擬似映像では、図面上の置き場所と映像上の位置のずれは中央値で約1画素
  （映像幅480画素）、図面画像に直して約4画素だった。
- 同時に追う図面は1枚。読み込んだモデルは2件まで保持し、古いものから捨てる。
